# PhoneBox X (iOS)

Native SwiftUI iPhone client for the existing PhoneBox desktop agent. This is an initial implementation scaffold, not a claim that every Android widget has already been ported.

## Architecture

- iOS app: SwiftUI, URLSession, Keychain, QR scanner, SSE reader, trackpad gestures.
- Desktop: keep the upstream `PhoneBox.Agent` unchanged.
- Pairing: scans the QR link generated by the desktop agent, validates the pinned SHA-256 certificate fingerprint, then exchanges the one-time code at `POST /api/pair/claim`.
- Runtime: requests go directly to the desktop agent over HTTPS on the LAN/Tailscale network.

## Windows-only development

You do not need a local Mac to edit the code. iOS compilation requires Apple's toolchain (Xcode/macOS). Use the included GitHub Actions workflow on a hosted macOS runner to compile and run simulator tests.

A simulator build does not create an installable iPhone IPA. Installing on a physical iPhone requires Apple signing credentials and a provisioning profile (normally an Apple Developer account). Add the secrets listed in `.github/workflows/ios.yml` only when you are ready to sign.

## Start

1. Fork or clone `https://github.com/ersinkoc/phonebox`.
2. Copy this `iOS/` folder into the repo root (or keep this as a separate repo).
3. Open `iOS/PhoneBoxX.xcodeproj` on a Mac, or push to GitHub and run the `iOS CI` workflow.
4. On the PC, install/run the existing PhoneBox Agent and enable LAN access in its settings.
5. In the agent settings, create a pairing QR code. In PhoneBox X, choose **Pair a PC** and scan it.
6. iPhone and PC must be on the same Wi-Fi, or both connected to the same Tailscale network.

## Important compatibility notes

- The agent's pairing QR link is `https://ersinkoc.github.io/phonebox/pair/#v=1&pc=...&fp=...&port=...&h=...&c=...`. The values are in the URL fragment.
- The one-time pairing code is exchanged only over TLS after validating the certificate fingerprint. The code itself is never sent to a browser page.
- This initial client implements the connection layer, system overview, common controls, SSE event feed, and trackpad. Full parity requires porting the remaining PhoneBox web widgets and their exact per-widget request payloads from `android/app/src/main/assets/www/` and the agent's `widgets.json`. Do not assume all widgets are present yet.
- The current agent has a LAN allow-list. Requests outside that list are expected to be rejected.
